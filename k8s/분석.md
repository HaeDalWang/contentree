# k8s 환경 분석 (고객 실제 운영 구축 기준)

고객 실제 환경에서 사용 중인 Kubespray 기반 Kubernetes 클러스터 및 Helmfile/Helmchart 구성을 분석한 문서이다.

---

## 1. 디렉터리 구조 요약

| 경로 | 설명 |
|------|------|
| `kubespray/` | Kubespray 인벤토리, 변수, HAProxy/Keepalived 커스텀 플레이북 |
| `helm/` | Helmfile 정의 및 각 차트별 values (실제 배포 스펙) |
| `helmchart/` | Helmfile에 포함되지 않은 차트/매니페스트 (Kafka, MariaDB, RabbitMQ, Vault, Kubecost 등) |

## 2. Kubespray 분석

### 2.1 인프라 토폴로지

- **제어 평면(Control Plane)**: 3노드

- **인프라(Infra)**: 3노드  
  - `mvd-kubein01` ~ `mvd-kubein03` (10.150.46.23–25), 라벨 `role=infra`
- **라우터(Ingress)**: 2노드  
  - `mvd-kubert01` ~ `mvd-kubert02` (10.150.44.16–17), 라벨 `role=router`
- **스토리지**: 3노드

- **HAProxy(L4 LB)**: 2노드  
  - `mvd-kubeha01`, `mvd-kubeha02` (10.150.46.30–31)  
  - VIP: `10.150.46.249` (Keepalived, `kube_haproxy` 그룹)

접속: Ansible 포트 4490, 사용자 `bluesky`, become 사용.

### 2.2 네트워크/CNI

- **CNI**: Calico  
  - `calico_ipip_mode: Always`, `calico_vxlan_mode: Never`, `calico_network_backend: bird`
- **kube-proxy**: IPVS
- **서비스 CIDR**: 10.233.0.0/18  
- **Pod CIDR**: 10.233.64.0/18  
- **노드당 Pod 서브넷 prefix**: /24

### 2.3 API 서버 부하 분산

- `apiserver_loadbalancer_domain_name` / `loadbalancer_apiserver.address`: `10.150.46.249`
- kubeconfig의 server 주소는 위 VIP로 설정되는 구조로 추정 (variables.yaml 주석 기준).

### 2.4 커스텀 HAProxy 플레이북 (`extra_playbooks/haproxy/`)

- **대상**: `kube_haproxy` (mvd-kubeha01, mvd-kubeha02)
- **구성 요소**: HAProxy 2.4.18, Keepalived 2.2.4, Ubuntu
- **프론트엔드**  
  - `kube_cp`: 6443 → 백엔드 `kube_cp_nodes` (3개 CP 노드 6443, roundrobin)
  - `kube_ingress`: 80/443 → 백엔드 `kube_ingress_nodes` (라우터 노드 2대, port 80)
  - `stats`: 9999 (HTTP, `/stats`)
- **Keepalived**: VIP `{{ haproxy_vip }}` (10.150.46.249), 인터페이스 `ens160`, `nopreempt`, state BACKUP, priority 100
- 로그: `/logs/haproxy/haproxy.log`, rsyslog + logrotate 설정

### 2.5 보안(Hardening) 요약

- **인증**: Node + RBAC, anonymous auth true (kubeadm join 호환)
- **API**: request timeout 120s, service account lookup 활성화
- **감사**: 활성화, `/var/log/kube-apiserver-log.json`, maxage 30, maxbackups 10, maxsize 100
- **TLS**: 최소 1.2, 지정 cipher suite 사용
- **Secret at-rest 암호화**: secretbox, `secrets` 리소스
- **Admission**: EventRateLimit, AlwaysPullImages, ServiceAccount, NamespaceLifecycle, NodeRestriction, LimitRanger, ResourceQuota, Mutating/Validating Webhook, PodNodeSelector
- **Pod Security**: 기본 정책 사용, enforce `restricted`, kube-system, ingress-nginx, rook-ceph, argocd, prometheus 등 다수 네임스페이스 제외
- **기타**: kubelet webhook 인증/인가, read-only port 0, 인증서 로테이션, seccomp default, 이미지 GC (low 60%, high 70%)

### 2.6 기타 Kubespray 설정

- **인증서**: 자동 갱신(calendar 기반)
- **레지스트리**: Harbor `k8s-harbor.joins.net`, robot 계정으로 containerd 인증
- **프록시**: `private` 그룹(CP, worker, infra, storage)에 `http(s)_proxy: dev-mkube-proxy.joins.net:3128`, `additional_no_proxy`에 Harbor
- **DNS/etchosts**: VIP 및 Harbor 등 도메인 매핑 (dev-mkube-argocd, prometheus, grafana, k8s-harbor 등)
- **아티팩트**: `/kubespray/artifacts`, admin.conf 복사 스크립트 `custom_scripts/cp_cert_bastion.sh` (실행 시 `/sw/kubespray` 기준)

## 6. 정리 및 권장 사항

1. **Kubespray**: HA 구성(3 CP, HAProxy+Keepalived VIP), 역할별 노드 분리(worker/infra/router/storage), Calico/IPVS, 보안 강화 및 Harbor/프록시 반영이 잘 되어 있음.
2. **Helmfile**: 인그레스, Rook-Ceph, Argo CD, 모니터링(kube-prometheus-stack, loki), 로깅(fluent-bit), 백업(Velero+MinIO), x509/메트릭 등 실제 운영에 필요한 구성이 정의되어 있음.
3. **OpenSearch**: helmfile에만 정의되어 있고 레포/values가 없음. opensearch Helm 레포 추가 및 `values/opensearch.yaml` 작성 또는 해당 release 제거/주석 처리 필요.
4. **helmchart/**: Kafka(Strimzi), MariaDB, RabbitMQ, Vault, Kubecost 등은 Helmfile과 별도 관리로 보이므로, Argo Application/디렉터리 구조와 함께 문서화해 두면 유지보수에 유리함.
5. **민감 정보**: variables.yaml, credentials, argocd/velero 등에 패스워드/시크릿이 포함될 수 있으므로, 분석 문서와 저장소는 접근 제어 및 비밀 제거 정책을 적용하는 것이 좋음.
